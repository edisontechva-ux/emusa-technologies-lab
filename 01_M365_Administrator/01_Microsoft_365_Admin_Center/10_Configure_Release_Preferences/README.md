# Configure Release Preferences

## Overview

Release Preferences determine how Microsoft 365 feature updates and new capabilities are delivered to users within the tenant. Administrators can control whether users receive new features immediately through Targeted Release or receive them later through Standard Release after Microsoft completes broader deployment and validation.

## Location

**Microsoft 365 admin center → Settings → Org settings → Release preferences**

## Steps

1. Opened the **Microsoft 365 admin center**.
2. Navigated to **Settings → Org settings**.
3. Selected **Release preferences** from the Services tab.
4. Reviewed the available release options:
   - Standard Release
   - Targeted Release for everyone
   - Targeted Release for selected users
5. Reviewed the release preference currently configured for the tenant.
6. Compared each release option and its impact on feature availability.
7. Selected the appropriate release preference based on organizational requirements.
8. If **Targeted Release for selected users** was chosen, selected the users who would receive early feature updates.
9. Reviewed the release preference configuration before applying the change.
10. Clicked **Save** to apply the configuration.
11. Waited for Microsoft 365 to process the update.
12. Verified that the selected release preference was successfully applied.
13. Confirmed the release preference status reflected the expected configuration.

## Result

The Microsoft 365 release preference settings were successfully reviewed and configured. The tenant is configured to receive Microsoft 365 feature updates according to the selected release strategy, ensuring feature deployment aligns with organizational testing and change management requirements.

## Administrative Notes

Microsoft 365 provides three release preference options:

- **Standard Release** delivers new features to users after Microsoft completes validation and deployment across the service.
- **Targeted Release for everyone** delivers new features to all users in the tenant before Standard Release.
- **Targeted Release for selected users** delivers new features only to designated users for testing and validation purposes.

Organizations commonly use **Targeted Release for selected users** to evaluate new Microsoft 365 features before deploying them to the entire user population. This approach helps identify potential usability, compatibility, or training requirements prior to broader adoption.
